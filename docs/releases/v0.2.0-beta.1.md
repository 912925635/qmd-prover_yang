# QMD-Prover v0.2.0-beta.1

这是证明审查工作台的预发布版本，供受控试用和反馈。发布对象是
`912925635/qmd-prover_yang` Fork，不是上游 `powergiant/qmd-prover`。

## 新增功能

- 会话追溯：保留独立 attempt、Codex 事件与会话身份，提供只读查看及显式讨论恢复。
- TeX–QMD 绑定：保存源锚点、上下文指纹及独立一致性证据；稿件 stale 不直接清除数学缓存。
- 冻结计划与并行队列：并发 1–3，单写入者提交，提交前重新检查源与所有权。
- 审查历史与比较：保留多轮结果，比较输入及 checker contract，不以模型投票改判。
- 任务控制与成本：提供 pause、resume、cancel、recover、retry、watch 和显式费率估算。
- 静态工作台：分别展示执行、提交、数学及稿件状态，刷新和只读查询不调用模型。

## Windows 修复

正式 runner 首次初始化曾让多个进程同时编译同一个 Job supervisor EXE，产生
CS0016 文件占用及连带测试失败。现在改为独立临时文件编译、完整 EXE 原子发布，
同进程请求合并初始化，并保留编译器 stdout/stderr。没有降低执行策略、放宽
既有超时或提供脱离 Job Object 的回退。

同时处理旧版 Framework 编译器的 MAX_PATH 限制：在短临时目录编译源副本，
再用 Node 文件 API 发布。当应用数据路径过长时，使用按该源根隔离的用户临时
缓存，保留完整源码摘要，避免 CLR 从超长路径启动。长路径冷启动并发已加入回归测试。

## 已知限制

- Windows 尚未完整验证控制器突然崩溃后的封存复用与恢复；进程清理测试不替代该验证。
- T8 尚未逐一覆盖 cache、journal、snapshot、pointer 的全部真实崩溃窗口。
- T10 尚未实现完整的意见回应证据关联及后台多模型历史专用任务。
- 所有权协调限于同主机本地文件系统，不提供跨主机或网络挂载的分布式写入保证。
- 没有真实模型准确率、完整兼容性或节省 Token 的比较结论。

Shadow Review 的数学 outcome 仍为 `inconclusive`。执行或自动测试成功不构成数学
正确性证明，也不能单独授予正式 `verified/rejected`。

## 安装与使用

需要 Node.js 20+。真实 QMD 解析需要 Pandoc，Quarto 仅用于最终文档渲染。
Windows 正式 runner 使用系统 .NET Framework 4.x C# 编译器准备 Job helper。

从本次 GitHub 预发布资产下载 tarball，核对 SHA256SUMS.txt 后安装：

```powershell
npm install -g ./qmd-prover-0.2.0-beta.1.tgz
qmd-prover version
qmd-prover doctor
qmd-prover install --global --codex
```

已有项目不会因安装自动迁移。沿用原有数学协议与缓存检查规则；操作已有项目之前
先保留源文件及 `.qmd-prover` 数据。会话恢复和 AI 一致性审查是显式操作，可能产生
模型用量；本次发布流程不运行真实模型。
